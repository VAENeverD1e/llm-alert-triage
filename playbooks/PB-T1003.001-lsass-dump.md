# Playbook - T1003.001: LSASS Memory Dump

| Field          | Value                                              |
|----------------|----------------------------------------------------|
| Technique      | T1003.001 - OS Credential Dumping: LSASS Memory    |
| Severity       | High                                               |
| Detection rule | `LSASS Memory Access`                              |
| Primary signal | Sysmon Event ID 10 (ProcessAccess)                 |
| MITRE tactic   | Credential Access (TA0006)                         |

---

## What triggered this alert

A process accessed `lsass.exe` with a high-privilege access mask
associated with credential dumping tools (Mimikatz, ProcDump,
comsvcs.dll MiniDump). The detection fires on access masks
`0x1fffff`, `0x1010`, `0x1410`, `0x143a`, or `0x1438`, excluding
known-legitimate callers (svchost+0x1410, wmiprvse+cimwin32,
security agents).

This is one of the highest-priority alerts in the ruleset. A confirmed
true positive means credentials are likely already extracted and the
attacker can move laterally using stolen hashes or Kerberos tickets.

---

## Triage steps

**Step 1 - Identify the accessing process**

In Kibana, inspect the following fields on the Sysmon Event ID 10:

```
process.name                         ← the process that opened lsass
process.executable                   ← full path
winlog.event_data.GrantedAccess      ← access mask (key field)
winlog.event_data.CallTrace          ← DLL call stack
winlog.event_data.TargetImage        ← should end in lsass.exe
host.name
user.name
@timestamp
```

**Step 2 - Interpret the access mask**

| Mask       | Tool association                     | Risk     |
|------------|--------------------------------------|----------|
| `0x1fffff` | PROCESS_ALL_ACCESS - Mimikatz/comsvcs| CRITICAL |
| `0x1010`   | VM_READ + QUERY_INFO - various tools | High     |
| `0x1410`   | Common Mimikatz mask                 | High     |
| `0x143a`   | Common ProcDump mask                 | High     |
| `0x1438`   | Alternative dump mask                | High     |

**Step 3 - Inspect the CallTrace**

`winlog.event_data.CallTrace` shows which DLLs were on the call stack.

| CallTrace contains     | Interpretation                              |
|------------------------|---------------------------------------------|
| `comsvcs.dll`          | LOLBin dump via `rundll32 comsvcs MiniDump` |
| `dbghelp.dll`          | ProcDump or legitimate debugger             |
| `cimwin32.dll`         | Legitimate WMI - FALSE POSITIVE             |
| `ntdll.dll` only       | Direct syscall - advanced attacker          |
| `mimilib.dll`          | Mimikatz - CONFIRMED MALICIOUS              |

**Step 4 - Check for a dump file**

If comsvcs.dll is in the CallTrace, search for the output file:

```powershell
# On the affected host - check the most likely locations first.
# %TEMP% resolves to C:\Users\<user>\AppData\Local\Temp in a user session,
# NOT C:\Windows\Temp. Check both explicitly before falling back to a
# recursive scan (which is slow and generates noisy disk I/O).
Get-ChildItem "$env:TEMP", "C:\Windows\Temp" -Include *.dmp -ErrorAction SilentlyContinue |
  Sort-Object LastWriteTime -Descending

# Only recurse into user profiles if the above returns nothing
# Get-ChildItem C:\Users -Recurse -Include *.dmp -ErrorAction SilentlyContinue
```

**Step 5 - Check for upstream execution**

Search for what launched the accessing process, ±2 minutes:

```kql
host.name: "<hostname>" AND
event.code: 1 AND
process.name: "<source_process>" AND
@timestamp: [<alert_time - 2m> TO <alert_time + 2m>]
```

Common attack chain: `powershell.exe` spawns `rundll32.exe` → accesses
`lsass.exe` → dump file written to `%TEMP%`.

## TP vs FP escalation criteria

**Treat as TRUE POSITIVE if any of the following:**

- Source process is `rundll32.exe`, `mimikatz.exe`, `procdump.exe`,
  `taskmgr.exe` (outside normal admin hours), or any unknown binary
- `comsvcs.dll` or `dbghelp.dll` appears in CallTrace from a
  non-administrative context
- A `.dmp` file is created in `%TEMP%` around the same timestamp
- The accessing process path is non-standard (e.g. `C:\Users\...`)
- Access mask is `0x1fffff` from anything other than a known security tool

**Treat as FALSE POSITIVE if all of the following:**

- Source is a known security product not in the exclusion list
  (add to filter after verification)
- CallTrace shows only `cimwin32.dll` (WMI stack - already excluded)
- Access mask is `0x1410` and source is `svchost.exe`
  (Windows authentication service - already excluded)

**Escalate immediately if:**

- Mimikatz artifacts (`mimilib.dll`, `sekurlsa`) are found anywhere
- The dump file has been exfiltrated (check for outbound connections
  immediately after the dump timestamp)
- Multiple accounts show authentication failures from other hosts
  shortly after this alert (pass-the-hash attempt in progress)

---

## Containment and response actions

**For confirmed TRUE POSITIVE:**

1. **Treat all credentials on this host as compromised.** This is
   non-negotiable - LSASS contains NTLM hashes for every account
   that has logged in since the last reboot.

2. **Isolate the host immediately** to prevent pass-the-hash lateral
   movement to other systems.

3. **Preserve the dump file** (for forensic analysis) before deletion:

   ```powershell
   # comsvcs.dll MiniDump writes to the path specified in the command line,
   # typically %TEMP% (C:\Users\<user>\AppData\Local\Temp) in a user session.
   # Copy from both locations to avoid missing the actual dump file.
   Copy-Item "$env:TEMP\*.dmp" -Destination "\\forensic-share\<case_id>\" -ErrorAction SilentlyContinue
   Copy-Item "C:\Windows\Temp\*.dmp" -Destination "\\forensic-share\<case_id>\" -ErrorAction SilentlyContinue
   ```

4. **Force password reset** for all accounts that have authenticated
   on this host, prioritizing privileged accounts (Domain Admins,
   service accounts).

5. **Check for lateral movement** - search for successful logon events
   (Event ID 4624, LogonType 3) from this host to other hosts in the
   30 minutes following the alert:

   ```kql
   event.code: 4624 AND
   winlog.event_data.LogonType: 3 AND
   source.ip: "<affected_host_ip>"
   ```

6. **Rotate Kerberos tickets** (krbtgt password reset x2) if a Domain
   Admin account was cached on the compromised host.

7. **Re-image the host.** Do not attempt to clean a post-credential-dump
   host - assume full compromise.

**For lab environment (Atomic Red Team):**

```powershell
Invoke-AtomicTest T1003.001 -TestNumbers 2 -Cleanup
# Verify dump file is removed:
Test-Path "$env:TEMP\lsass-comsvcs.dmp"  # should return False
```

## Evidence collection checklist

- [ ] Sysmon Event ID 10 - full record with all fields
- [ ] `process.name` and `process.executable` (source process)
- [ ] `winlog.event_data.GrantedAccess` (access mask)
- [ ] `winlog.event_data.CallTrace` (full DLL stack)
- [ ] `user.name` and `host.name`
- [ ] `@timestamp` of the alert
- [ ] Sysmon Event ID 1 - what launched the source process?
- [ ] Filesystem - presence and size of any `.dmp` files in `%TEMP%`
- [ ] Sysmon Event ID 3 - any outbound connections after dump creation?
- [ ] Windows Event ID 4624 - lateral movement attempts from this host?
- [ ] Screenshot of Kibana alert with GrantedAccess field visible
