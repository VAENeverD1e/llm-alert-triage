# Playbook - T1547.001: Registry Run Key Persistence

| Field          | Value                                              |
|----------------|----------------------------------------------------|
| Technique      | T1547.001 - Boot/Logon Autostart: Registry Run Key |
| Severity       | Medium                                             |
| Detection rule | `Registry Run Key Persistence`                     |
| Primary signal | Sysmon Event ID 13 (RegistryValueSet)              |
| MITRE tactic   | Persistence (TA0003)                               |

---

## What triggered this alert

A process wrote a new value to a Windows Registry Run or RunOnce key,
which causes the referenced executable to launch automatically at
user logon or system startup. Known-legitimate writers (MsMpEng.exe,
svchost.exe, OneDrive.exe) are excluded. Any other writer is flagged.

This is a Medium severity alert because legitimate software also uses
Run keys. The goal is to confirm whether the write came from an
authorized installer or a persistence implant.

---

## Triage steps

**Step 1 - Identify the write**

Inspect the Sysmon Event ID 13 record:

```
registry.path       ← full key path including the value name
registry.value      ← the data written (path to executable)
process.name        ← what wrote to the key?
process.executable  ← full path of the writing process
user.name
host.name
@timestamp
```

**Step 2 - Evaluate the registry value data**

The value data (`registry.value`) is the executable that will run
at logon. Ask:

- Is the path in a standard software location (`C:\Program Files\...`)?
- Or in a user-writable location (`C:\Users\...\AppData`, `C:\Temp`)?
- Does the executable exist on disk?

```powershell
# On the affected host - check if the binary exists and is signed.
# Registry Run values often contain arguments (e.g. "cmd.exe /c calc.exe").
# Extract only the executable token before calling Test-Path or Get-AuthenticodeSignature;
# passing the full string with arguments causes both to fail silently.
$rawValue = "<registry_value_data>"
$executablePath = ($rawValue -split ' ')[0].Trim('"')
Test-Path $executablePath
Get-AuthenticodeSignature $executablePath | Select-Object Status, SignerCertificate
```

**Step 3 - Check the writing process**

| Writing process             | Interpretation                                    |
|-----------------------------|---------------------------------------------------|
| `msiexec.exe`               | Software installer - likely legitimate            |
| `setup.exe` / `install.exe` | Software installer - verify vendor                |
| `powershell.exe`            | Script-based persistence - high suspicion         |
| `cmd.exe`                   | Script-based persistence - high suspicion         |
| `reg.exe`                   | Manual registry manipulation - investigate        |
| Unknown binary              | Likely malware - escalate immediately             |

**Step 4 - Cross-reference with prior events**

Search for what ran before the registry write, ±5 minutes:

```kql
host.name: "<hostname>" AND
event.code: 1 AND
@timestamp: [<alert_time - 5m> TO <alert_time + 5m>]
```

Look for: encoded PowerShell, downloaded executables, or any process
spawned from a browser or email client (initial access chain).

**Step 5 - Check for additional persistence keys**

If the write is suspicious, broaden the search:

```kql
host.name: "<hostname>" AND
event.code: 13 AND
registry.path: (*\\CurrentVersion\\Run* OR *\\CurrentVersion\\RunOnce*
  OR *\\CurrentVersion\\RunServices* OR *\\Winlogon*
  OR *\\WOW6432Node\\*\\CurrentVersion\\Run*)
```

## TP vs FP escalation criteria

**Treat as TRUE POSITIVE if any of the following:**

- The executable path points to a user-writable directory
  (`%APPDATA%`, `%TEMP%`, `C:\Users\...`)
- The executable is not signed or has an invalid/expired signature
- The writing process is `powershell.exe`, `cmd.exe`, or `reg.exe`
  without a prior legitimate installer event
- The value name is random-looking (e.g. `a3f9bc21`) rather than a
  recognizable software name
- A download or dropper event preceded this write in the timeline

**Treat as FALSE POSITIVE if all of the following:**

- The executable path is under `C:\Program Files\` or
  `C:\ProgramData\` with a valid vendor signature
- The writing process is an installer (`msiexec.exe`, `setup.exe`)
  with a matching software installation event in Add/Remove Programs
- The value name matches a known software product

**Escalate immediately if:**

- The Run key persistence follows an LSASS access alert
  (credential dumping + persistence = active compromise)
- The registered executable is a reverse shell or RAT binary
- The same Run key write appears on multiple hosts simultaneously

## Containment and response actions

**For confirmed TRUE POSITIVE:**

1. **Remove the malicious Run key entry:**

   ```powershell
   # HKCU key (current user)
   Remove-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
     -Name "<value_name>" -ErrorAction SilentlyContinue

   # HKLM key (all users - requires admin)
   Remove-ItemProperty -Path "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run" `
     -Name "<value_name>" -ErrorAction SilentlyContinue

   # 32-bit subsystem key on 64-bit Windows - also check this
   Remove-ItemProperty -Path "HKLM:\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Run" `
     -Name "<value_name>" -ErrorAction SilentlyContinue
   ```

2. **Delete the registered executable** (after preserving a copy for
   forensic analysis):

   ```powershell
   Copy-Item "<executable_path>" -Destination "\\forensic-share\<case_id>\"
   Remove-Item "<executable_path>" -Force
   ```

3. **Kill any running instance** of the registered executable:

   ```powershell
   Stop-Process -Name "<executable_name>" -Force
   ```

4. **Search for other persistence mechanisms** on the same host -
   a Run key implant rarely arrives alone:
   - Scheduled tasks: `schtasks /query /fo LIST /v`
   - Services: `sc query type= all state= all`
   - Startup folder: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`

5. **Determine the infection vector** by tracing the process tree
   backward from the writing process.

6. **Revert to a clean snapshot** if the scope of compromise is
   unclear. A persistence implant indicates the attacker has had
   dwell time.

**For lab environment (Atomic Red Team):**

```powershell
Invoke-AtomicTest T1547.001 -TestNumbers 1 -Cleanup
# Verify:
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
  Select-Object "Atomic Red Team"
# Should return nothing
```

## Evidence collection checklist

- [ ] Sysmon Event ID 13 - full record
- [ ] `registry.path` - full key path and value name
- [ ] `registry.value` - data written (executable path)
- [ ] `process.name` and `process.executable` - writing process
- [ ] `user.name` and `host.name`
- [ ] `@timestamp`
- [ ] Authenticode signature status of the registered executable
- [ ] Sysmon Event ID 1 - process tree leading to the write
- [ ] Any download events preceding the Run key write
- [ ] Screenshot of Registry Editor confirming the entry (before removal)
- [ ] Hash (SHA256) of the registered executable
