# Playbook - T1055.001: DLL Injection via mavinject.exe

| Field          | Value                                                    |
|----------------|----------------------------------------------------------|
| Technique      | T1055.001 - Process Injection: DLL Injection             |
| Severity       | High                                                     |
| Detection rule | `DLL Injection via CreateRemoteThread`                   |
| Primary signal | Sysmon Event ID 1 (process creation)                     |
| MITRE tactic   | Defense Evasion (TA0005) / Privilege Escalation (TA0004) |

---

## What triggered this alert

> **Rule name note:** The Kibana rule is titled "DLL Injection via
> CreateRemoteThread" - a legacy name. mavinject.exe does **not**
> trigger Sysmon Event ID 8 (CreateRemoteThread); it uses `NtCreateThreadEx`
> directly. The actual detection artifact is Sysmon **Event ID 1**
> (process creation). Do not spend time looking for an Event ID 8 that
> will never appear.

`mavinject.exe` - a legitimate Microsoft App-V binary - was launched
with the `/INJECTRUNNING` flag from a parent process that is not a
recognized App-V infrastructure component (msiexec.exe, AppVClient.exe).
This is the standard LOLBin abuse pattern for DLL injection: using a
signed Microsoft binary to load a malicious DLL into a running process
while appearing trusted.

**Key technical note:** Event ID 8 (CreateRemoteThread) will NOT fire
for mavinject.exe. It uses `NtCreateThreadEx` directly, bypassing the
Win32 API hook Sysmon relies on. Event ID 1 on process creation is
the only reliable detection artifact for this technique.

## Triage steps

**Step 1 - Extract the injection parameters**

Inspect the Sysmon Event ID 1 for `mavinject.exe`:

```
process.command_line    ← includes target PID and DLL path
                          format: mavinject.exe <PID> /INJECTRUNNING "<DLL>"
process.parent.name     ← what called mavinject?
process.parent.command_line
user.name
host.name
@timestamp
```

Parse the command line to extract:

- **Target PID** - which process was injected into?
- **DLL path** - what was injected?

**Step 2 - Identify the target process**

Resolve the target PID to a process name. Cross-reference Sysmon
Event ID 1 records near the alert timestamp:

```kql
host.name: "<hostname>" AND
event.code: 1 AND
@timestamp: [<alert_time - 30s> TO <alert_time + 30s>]
```

High-value injection targets attackers prefer:

- `explorer.exe` - runs persistently, high privilege in user context
- `svchost.exe` - blends with system traffic
- `notepad.exe` / benign apps - used in lab simulations

**Step 3 - Evaluate the injected DLL**

Check whether the DLL path exists and inspect it:

```powershell
$dllPath = "<extracted DLL path from command line>"
Test-Path $dllPath
Get-AuthenticodeSignature $dllPath | Select-Object Status, SignerCertificate
Get-FileHash $dllPath -Algorithm SHA256
```

Submit the hash to VirusTotal or your threat intel platform.

**Step 4 - Check for DLL behavior after injection**

After injection, the DLL code runs inside the target process. Search
for suspicious behavior attributed to the target process:

```kql
host.name: "<hostname>" AND
process.pid: <target_PID> AND
event.code: (3 OR 11 OR 13) AND
@timestamp: [<alert_time> TO <alert_time + 10m>]
```

Look for: outbound network connections, file writes, registry writes
attributed to what should be a benign host process.

**Step 5 - Check the parent process chain**

```kql
host.name: "<hostname>" AND
event.code: 1 AND
process.name: "<parent_of_mavinject>" AND
@timestamp: [<alert_time - 5m> TO <alert_time>]
```

Common attack chain: `powershell.exe` → `mavinject.exe /INJECTRUNNING`
→ injected DLL runs inside target process.

## TP vs FP escalation criteria

**Treat as TRUE POSITIVE if any of the following:**

- Parent process is `powershell.exe`, `cmd.exe`, or any user process
  (not an App-V binary)
- The DLL path is in a user-writable directory or temp location
- The DLL is unsigned or has an unrecognized publisher
- Post-injection, the target process initiates outbound network
  connections it would not normally make
- The environment does not use Microsoft App-V

**Treat as FALSE POSITIVE if all of the following:**

- Parent process is `AppVClient.exe` or `msiexec.exe`
- The DLL path is under `C:\Program Files\Microsoft Application
  Virtualization\`
- The environment is documented as an App-V deployment

**Escalate immediately if:**

- Post-injection network activity from the target process is observed
- The injected DLL is identified as a known RAT or stager payload
- Injection targets a privileged process (`lsass.exe`, `winlogon.exe`,
  security tools) - this indicates privilege escalation intent

## Containment and response actions

**For confirmed TRUE POSITIVE:**

1. **Kill the target process** to terminate the injected DLL's
   execution thread.

   > ⚠️ **Before killing any process by PID, verify the target process
   > name.** Killing `csrss.exe`, `lsass.exe`, `winlogon.exe`, or
   > `smss.exe` will cause an immediate BSOD. Killing `explorer.exe`
   > terminates the analyst's desktop session. Always resolve the PID
   > to a process name first:
>
   > ```powershell
   > Get-Process -Id <target_PID> | Select-Object Name, Path
   > ```

   ```powershell
   # Only proceed after confirming the process name is safe to kill
   Stop-Process -Id <target_PID> -Force
   ```

1. **Kill the mavinject.exe process** if still running:

   ```powershell
   Stop-Process -Name mavinject -Force
   ```

2. **Preserve the injected DLL** for forensic analysis before any
   cleanup:

   ```powershell
   Copy-Item "<DLL_path>" -Destination "\\forensic-share\<case_id>\"
   Get-FileHash "<DLL_path>" -Algorithm SHA256
   ```

3. **Isolate the host** if post-injection network activity was
   observed - the DLL may have established C2 or begun lateral
   movement.

4. **Search for the DLL drop mechanism** - the DLL had to arrive
   on disk somehow. Search for download events:

   ```kql
   host.name: "<hostname>" AND
   event.code: (11 OR 15) AND
   file.name: "<dll_filename>"
   ```

5. **Check for co-located persistence** - process injection is often
   combined with Run key or scheduled task persistence to survive
   reboots.

6. **Submit the DLL hash** to threat intel for identification.

**For lab environment (Atomic Red Team):**

```powershell
Invoke-AtomicTest T1055.001 -TestNumbers 1 -Cleanup
Stop-Process -Name notepad -ErrorAction SilentlyContinue
# Verify DLL (remains on disk by design in lab):
Test-Path "C:\AtomicRedTeam\atomics\T1055.001\src\x64\T1055.001.dll"
```

## Evidence collection checklist

- [ ] Sysmon Event ID 1 - full `process.command_line` for mavinject.exe
- [ ] Target PID and resolved process name
- [ ] DLL path, file hash (SHA256), and signature status
- [ ] `process.parent.name` and full parent command line
- [ ] `user.name` and `host.name`
- [ ] `@timestamp`
- [ ] Post-injection events attributed to target process (ID 3, 11, 13)
- [ ] VirusTotal or threat intel result for DLL hash
- [ ] Copy of the injected DLL (preserved for forensics)
- [ ] Screenshot of Kibana alert showing `/INJECTRUNNING` in command line
