# Playbook - T1053.005: Scheduled Task Persistence

| Field          | Value                                              |
|----------------|----------------------------------------------------|
| Technique      | T1053.005 - Scheduled Task/Job: Scheduled Task     |
| Severity       | High                                               |
| Detection rule | `Suspicious Scheduled Task Creation`               |
| Primary signal | Sysmon Event ID 1 + Windows Event ID 4698          |
| MITRE tactic   | Execution (TA0002) / Persistence (TA0003)          |

---

## What triggered this alert

`schtasks.exe` was called with persistence triggers (`/sc onlogon`,
`/sc onstart`, `/sc once`, `/sc daily`) from a parent process other
than `svchost.exe` or `taskhostw.exe`. This pattern indicates a
non-system process registering an automatic execution task, which is
a common persistence technique. Two independent log sources capture
this: Sysmon Event ID 1 (process creation) and Windows Security
Event ID 4698 (task created).

---

## Triage steps

**Step 1 - Identify the task**

Inspect the Sysmon Event ID 1 for `schtasks.exe`:

```
process.command_line    ← full schtasks command including task name,
                          trigger (/sc), and action (/tr)
process.parent.name     ← what created the task?
process.parent.command_line
user.name
host.name
@timestamp
```

Also check Windows Event ID 4698 for richer task detail:

```kql
event.code: 4698 AND host.name: "<hostname>"
```

The 4698 event contains the full task XML including the action
executable path and all trigger conditions.

**Step 2 - Evaluate the task action**

Extract the `/tr` (task run) value from `process.command_line`. This
is what the task will execute. Ask:

- Is it a known executable in a standard path?
- Is it encoded PowerShell?
- Is it a network path (`\\server\share\...`)?
- Does the executable exist and is it signed?

```powershell
# Check on the affected host.
# The /tr value often contains arguments (e.g. "cmd.exe /c calc.exe").
# Extract the executable token only before calling Test-Path or Get-AuthenticodeSignature;
# passing the full string with arguments causes both to fail silently.
$rawAction = "<extracted /tr value>"
$executablePath = ($rawAction -split ' ')[0].Trim('"')
Test-Path $executablePath
Get-AuthenticodeSignature $executablePath | Select-Object Status, SignerCertificate
```

**Step 3 - Check the trigger**

| Trigger          | Attacker preference | Notes                              |
|------------------|---------------------|------------------------------------|
| `/sc onlogon`    | High                | Runs every time any user logs in   |
| `/sc onstart`    | High                | Runs at every system boot          |
| `/sc daily`      | Medium              | Beacon-style periodic execution    |
| `/sc once`       | Low                 | One-time delayed execution         |

**Step 4 - Check the parent process**

| Parent process         | Interpretation                                 |
|------------------------|------------------------------------------------|
| `powershell.exe`       | Script-based task creation - high suspicion    |
| `cmd.exe`              | Script-based task creation - high suspicion    |
| `msiexec.exe`          | Software installer - verify vendor             |
| Unknown binary         | Likely malware - escalate immediately          |

**Step 5 - Verify whether the task ran**

Check if the task executed after creation:

```powershell
# On the affected host
Get-ScheduledTaskInfo -TaskName "<task_name>" |
  Select-Object LastRunTime, LastTaskResult, NextRunTime
```

## TP vs FP escalation criteria

**Treat as TRUE POSITIVE if any of the following:**

- The task action points to a user-writable directory or temp path
- The task action is encoded PowerShell or a download cradle
- The task name is random-looking or impersonates a system task
  (e.g. `WindowsUpdate`, `MicrosoftEdgeUpdate`)
- The creating process is not a recognized software installer
- The task was created by a non-administrative user account
- A Run key write or LSASS access alert preceded this event

**Treat as FALSE POSITIVE if all of the following:**

- The task action points to a signed executable in `Program Files`
- The creating parent is a recognized installer (`msiexec.exe`,
  `setup.exe`) with a matching software installation in the timeline
- The task name matches the installed software product
- The task is visible and expected in Task Scheduler

**Escalate immediately if:**

- The task action downloads and executes a remote payload
- The task is created on multiple hosts near-simultaneously
- The task is created under `SYSTEM` context from a user-level process

## Containment and response actions

**For confirmed TRUE POSITIVE:**

1. **Delete the malicious scheduled task:**

   ```powershell
   # Prefer the native command - works across all shells without
   # requiring the ScheduledTasks PowerShell module or elevation context.
   schtasks /delete /tn "<task_name>" /f

   # PowerShell alternative (requires admin and ScheduledTasks module):
   Unregister-ScheduledTask -TaskName "<task_name>" -Confirm:$false
   ```

2. **Verify deletion:**

   ```powershell
   Get-ScheduledTask | Where-Object {$_.TaskName -eq "<task_name>"}
   # Should return nothing
   ```

3. **Kill any currently running task process:**

   ```powershell
   Stop-Process -Name "<task_action_process>" -Force
   ```

4. **Preserve task XML before deletion** for forensic record:

   ```powershell
   Export-ScheduledTask -TaskName "<task_name>" |
     Out-File "\\forensic-share\<case_id>\task_<name>.xml"
   ```

5. **Search for co-located persistence mechanisms:**
   - Registry Run keys (check PB-T1547.001)
   - Other scheduled tasks with similar action paths
   - New services: `Get-Service | Where-Object {$_.StartType -eq "Automatic"}`

6. **Determine the infection chain** - trace the parent process
   backward to find the initial access vector.

**For lab environment (Atomic Red Team):**

```powershell
Invoke-AtomicTest T1053.005 -TestNumbers 1 -Cleanup
# Verify:
Get-ScheduledTask | Where-Object {$_.TaskName -like "*T1053*"}
# Must return nothing
```

## Evidence collection checklist

- [ ] Sysmon Event ID 1 - full `process.command_line` for schtasks.exe
- [ ] Windows Event ID 4698 - full task XML (task name, action, trigger)
- [ ] `process.parent.name` and `process.parent.command_line`
- [ ] Task action executable - path, existence, signature status
- [ ] `user.name` and `host.name`
- [ ] `@timestamp` of creation
- [ ] Sysmon Event ID 1 - process tree leading to task creation
- [ ] `Get-ScheduledTaskInfo` output (LastRunTime, LastTaskResult)
- [ ] Screenshot of Task Scheduler showing the task (before deletion)
- [ ] Exported task XML
